# Security Rules

## 方針

セキュリティは機能実装より優先する。不明な場合は安全側を選択する。

## 環境変数・秘密情報

- 秘密情報（`MAIL_USER` / `MAIL_PASS` など）は環境変数で管理し、ソースコードへ直書きしない。
- `NEXT_PUBLIC_` に秘密情報を設定しない。
- **現状 `.env` が Git 管理されている。** `.env` の中身をコミット・PR・ログ・回答に出力しない。
  `.gitignore` の整備や履歴からの除去、パスワードの再発行は、ユーザーに確認してから行う。
- `.env.example` に変数名のみを記載して共有する。

## 入力検証（問い合わせフォーム / `app/api/postMail`）

- サーバー側で必ず検証する（クライアント検証だけに頼らない）。
  - 必須項目・型・文字数・メール形式・電話番号形式
- リクエストボディを検証せずに使わない。
- メールの HTML 本文にユーザー入力を埋め込む場合は **HTML エスケープ** する。
- ヘッダーインジェクション防止のため、`subject` / `from` に入力値の改行を含めない。
- `from` に利用者のメールアドレスを直接使わない（SMTP送信元の制約・なりすまし対策）。`replyTo` の利用を検討する。
- スパム・連投対策（レート制限、honeypot 等）の要否を確認する。

## エラーハンドリング

- 内部エラー・スタックトレースをクライアントへ返さない。
- 適切なHTTP Status（400 / 500 など）を返す。

## ログ

パスワード・Token・個人情報（氏名・メール・電話番号・本文）はログへ出力しない。

## 依存関係

- 不要なライブラリは追加しない。追加時は理由を説明する。
- `dangerouslySetInnerHTML` は原則使用しない。

## Checklist

- [ ] 秘密情報を公開していない
- [ ] `.env` の中身を出力していない
- [ ] サーバー側で入力値を検証した
- [ ] ユーザー入力をエスケープした
- [ ] エラー内容を必要以上に公開していない
